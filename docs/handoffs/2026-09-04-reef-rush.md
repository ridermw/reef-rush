## Hill climbing record

### Task 5 runtime investigation

Hosted baseline `33919453978` on `a9bd186` passed completely. The new collision
regressions then produced 16 expected failures with the three original movement
integration cases still passing. They cover thin barriers, initial and changed
rotations, collider removal and filters, live translation, parent transforms,
fish offsets, and live trigger geometry.

Replacing snapshots with live Rapier reads exposed a deeper loading defect:
the existing bundler package and file alias mix native WebAssembly callbacks
with Vitest's transformed JavaScript binding. Even `Collider.translation()`
fails, independently reproduced in `tests\integration\rapierRuntime.test.ts`.
Native Node import also fails on the package's extensionless ESM imports.

Preparation run `33920215947` generated npm metadata and cache for the official
`@dimforge/rapier3d-compat` build at the same `0.20.0` engine version. The complete
dependency diff changed only that package and its direct root entry; unrelated
versions and integrity hashes stayed unchanged. Local metadata matches those
npm generated artifacts exactly, and offline installation succeeded.

The compatible package, serialized initialization, and removal of the Vite file
alias made the isolated binding test pass. The temporary preparation mode was
removed from the workflow. Ordinary dispatch still performs the full baseline.
