### Slice 13B: explicit protected save recovery

Source inspection confirms that `progressStorage.ts` exposes guarded reads
and ordinary writes, not a reset API. Do not weaken `saveProgress` or add an
automatic fallback. Recovery needs a separate, explicit path.

**Design:** expose a native saved progress dialog from stationary shell screens,
not an interactive overlay during play/loading. Reuse the existing modal input,
focus, and Escape behavior. A small shared modal helper is preferable to copying
the Settings dialog's lifecycle/keyboard implementation.

- The dialog reads a fresh storage snapshot and clearly distinguishes valid,
  empty, malformed, unsupported, and unavailable storage. Never derive these
  states by parsing the human notice string.
- Offer a local backup download for invalid raw data. Use a JSON envelope
  containing the exact raw JavaScript string so even unmatched surrogate code
  units survive a round trip. Render preview text safely and bound its length;
  no raw data goes to logs, diagnostics, or a network service. Revoke owned
  object URLs when the dialog replaces its snapshot or closes.
- Unsupported versions remain protected: backup and guidance only, with no
  replacement action in this older game version.
- For malformed JSON or invalid version 1 schema, require a separate explicit
  acknowledgment before enabling replacement. Explain that the original save
  is replaced with progress actually earned in the current session, not silently
  reset on load. Keep a backup available before confirmation.
- Add a separate `replaceInvalidProgress` storage operation. Validate its
  replacement progress, obtain storage once, and require that the current read
  is still a replaceable invalid save with the exact raw value the player
  inspected. Do not clear the key before writing. Any valid, empty, changed,
  unsupported, unavailable, or failed write outcome must be explicit.
- GameHost queues the operation with its existing save work and acquires the
  same `reef-rush.progress` Web Lock. Reread under the lock, use the latest
  session progress there, and do not await between comparison and write.
  Concurrent cooperative writers and late earned records must be preserved.
  A failed recovery must not poison later queued saves or look successful.
- A changed save cancels replacement and requires a fresh inspection and
  confirmation. Valid/unavailable states can explicitly retry ordinary saving
  through the existing merge and invalid save safeguards. No import/editor,
  valid progress reset, extra backup storage key, or automatic retry loop.
- Preserve pending saves across navigation/disposal. Closing the dialog
  discards its authorization and restores focus; it must never resume a race.
  A replacement still waiting for the queue or lock must recheck cancellation
  before writing. Ordinary race saves remain durable; an already committed
  replacement must never be reported as rolled back merely because the dialog
  closed afterward.
  Keep the saved progress control stable on stationary screens so successful
  recovery does not remove the focus return target.

Implement this after 13A's publication gate. Storage, host queue, and native
dialog regressions must fail before their changes. Cover stale raw data, a
new valid save while waiting for the lock, unsupported versions, denied storage,
write failures, exact backup round trips, cancellation, and current session
record preservation. Browser evidence must include a real finish against an
invalid save followed by explicit recovery, and a real competing tab/Web Lock.
No actual user save outside the isolated test browser contexts is modified.

### Task 8 host and browser slice

`GameHost` is owned by main, not a transient screen. `setContainer` is a stable
React ref; detachment suspends the surface without abandoning its retry owner.
Only one canvas and animation chain may exist. Loading checks generations
after asynchronous boundaries; late resources are released, not attached.
`whenIdle()` and `dispose()` wait for loading and queued persistence. Failed
cleanup remains reachable through the host and `retryCleanup()`; new loading
is blocked until cleanup succeeds.

The fixed loop uses 1/60 second steps. Pause or finish aborts remaining catchup;
resume resets the wall timestamp and accumulator. Focus is checked before
attaching the canvas. Loading into an unfocused document pauses at zero time,
and focus return alone does not resume. Escape works on focused pause controls
without stealing native Space/Enter activation or editable input behavior.

`reef-rush.progress`, then synchronously reads current storage, merges it with
the latest session records, and writes through the protected storage helper.
`mergeProgress` takes minimum best time, maximum medal, and maximum pearl count
independently across the union of courses. Invalid current raw data remains
untouched. Missing coordination, unavailable storage, and write failures leave
session results visible with an explicit notice. Saving continues across title
navigation and disposal, but a blocked lock can delay awaiters.
